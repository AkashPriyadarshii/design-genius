# Contributing

Add a design system to the library and every user of the skill designs in that
direction. Keep the corpus honest.

## Adding a system (the high-value contribution)

1. Build a `DESIGN.md` for a real, distinctive brand or product — real hex
   tokens, full type scale, spacing, radius, motion, one signature detail.
   Don't invent it; extract it from something that exists.
2. Save it to `awesome-design-md/design-md/<name>/DESIGN.md` in the library
   (or the sibling corpus you use).
3. Make it substantive (13KB+). A stub is noise — the skill reads every block
   and a thin spec drags the fusion down.

## Rules

- No README-only repos or bare link lists — no token content, no value.
- Reject duplicates: check `awesome-design-md/design-md/` and
  `web-design/references/design-systems/` before adding a name that's already
  covered (apple, clay, linear, stripe, vercel… exist).
- Keep every file a real extractable spec, never a vibecode placeholder.

## Skill itself

Small, sharp diffs to `SKILL.md`. Eight levers and the audit gate are load-bearing —
don't weaken or reorder them. Pitch a change in a few lines, not an essay.
